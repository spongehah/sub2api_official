# 提示词审计多轮输入裁剪

## 修改范围

- `backend/internal/securityaudit/prompt_snapshot.go`
- `backend/internal/securityaudit/prompt_snapshot_test.go`

## 必要原因

Qwen3Guard 原先接收请求内所有角色的文本。多轮请求会重复发送历史 user、assistant/model 和工具调用内容，既增加审计节点负载，也会让已完成的上下文反复进入审核。

gateway 仍负责推理请求路径的提示词审计；本次仅在该路径的审计快照提取阶段筛选内容，不改变请求转发、队列、审计事件表或 admin 控制面。

## 本地行为

- 首轮保留所有 system 等价指令与最新 user 消息的全部文本块。
- 后续轮保留最新 user 消息，以及该消息之后的原生工具结果文本。Responses 同时识别标准 `function_call_output.output`、Codex `custom_tool_call_output.output`、`mcp_tool_call_output.output`、兼容层 `tool_search_output.output` 与托管 MCP `mcp_call.output`。`tool_search_output.tools` 是工具定义，不进入审计。
- assistant/model 历史、旧 user、工具调用参数、旧工具结果、图片、二进制和 data URL 不进入 Qwen3Guard 输入。
- WebSocket 优先使用 `first_turn` 与 `subsequent_turn` 阶段。HTTP 请求没有可靠的跨协议会话 ID，因此只根据当前请求中的 assistant/model 历史或工具结果判断后续轮，不新增 Redis 会话状态。
- 输入仍由 `SplitRunes` 按节点 `input_limit` 进行 Unicode 字符分片；命中 `Block` 或扫描失败会停止剩余分片。

## 验证方式

```bash
cd gateway/backend
GOTOOLCHAIN=auto GOCACHE=/tmp/go-cache GOTMPDIR=/tmp/go-tmp go test ./internal/securityaudit ./internal/handler ./internal/server/routes
git diff --check
```

测试覆盖 Chat Completions、Responses、Anthropic、Gemini 的首轮和后续轮，及其工具结果、WebSocket 阶段、Unicode 分片和阻断停扫行为。

## 后续处理

这是 gateway 本地的低侵入行为调整。若 official 后续提供同等的多轮审计输入裁剪，应优先切换到 official 实现并删除或缩小本地解析逻辑。
